# Owned offscreen D3D12 readback evidence

Date: 2026-11-12. Windows x64, WARP and DXGI hardware adapter 0. Default-off;
not linked into the desktop app. Design: ADR 0054.

## Implemented scope

Original offscreen D3D12 renderer with a private DIRECT queue and three slots.
Each slot owns a BGRA8 render target, RTV heap, allocator/list and READBACK buffer.
The renderer clears, transitions RENDER_TARGET -> COPY_SOURCE, copies to a placed
buffer footprint, and transitions back on its own queue. There is no swap chain,
Present detour, remote loading or game target in this implementation.

Submission reserves a slot, records/executes and signals a monotonically increasing
fence without waiting for completion. Poll checks the fence before Map and strips
row padding. CPU publications are immutable Arc bytes. GPU completion does not
release a consumer lease; a slot is recycled only after its weak-tracked CPU lease
has no strong owner. There is no overwrite or unlimited replacement on full rings.
UINT64_MAX completion is device loss, never permission to map. Errors close capture.

Dimensions are capped at 1920x1080 and readback footprints at 16 MiB per slot.
Three GPU targets, three readback buffers and three live CPU publications are
bounded within a session (temporary CPU conversion allocation may coexist).
Only one fixture may be active per process. Controller/worker teardown polls for
up to two seconds; uncertain completion retains GPU resources and permanently
holds the creation reservation rather than freeing in-flight resources/retrying.
Driver/API calls themselves do not have a hard completion-time guarantee.

## Reproduction

```powershell
.\scripts\test-game-capture-prototype.ps1 -Native -Hardware -Decode
```

The existing script now explicitly runs `d3d12_native` WARP/hardware lifecycle
tests and includes two `d3d12_replay` cases in the recorder filters. The standalone
native feature does not enable MinHook. Native cases remain ignored without opt-in.
Decode uses the existing exact hash-approved FFmpeg artifact, not a PATH lookup.

## Observed results

- Two new deterministic fence-slot tests passed: ordering, incomplete completion,
  device-removed sentinel, full ring, completion versus retained lease, stale/invalid
  release, closure and exhaustion. Existing deterministic timestamp/replay tests
  also passed; this fixture does not replace their contracts.
- WARP and hardware lifecycle cases passed at 318x178, 640x480 and 800x450.
  Width 318 deliberately requires padded D3D12 readback rows. All raw BGRA pixels
  matched the submitted red, green, blue and white values exactly.
- Three submitted slots rejected further admission. Retaining all three completed
  CPU frames still rejected admission in 12 repeated attempts. Releasing one lease
  admitted sequence 4 without changing retained red/blue bytes.
- Invalid colors/dimensions and simultaneous second fixture creation were rejected.
  Cancellation rejected further submissions/publications. Retained CPU pixels stayed
  valid after fixture destruction. Unpolled in-flight teardown completed normally.
- Sequential creation at new dimensions/devices passed, but this is NOT live resize
  or device-loss recovery. Neither terminal GPU loss nor a drain timeout was forced.
- RecorderEngine -> software Media Foundation H.264 -> replay buffer -> MP4 passed
  on both D3D12 drivers. Source was 318x178, requested 30 FPS, CPU BGRA payloads.
  Final full gate: WARP clip 846 ms, hardware clip 842 ms; both reported 39 capture
  readbacks, zero encoder GPU-surface inputs, and 25 saved color samples checked.
- MP4 checks cover dimensions, duration, at least ten samples, leading keyframe,
  monotonic sample start times and nonempty packets. Approved FFmpeg decoded every
  saved frame and checked the expected red primary-color sample for each frame.
  Color checks use downscaled frame samples, not full decoded pixel equality.
- Full prototype gate passed 26 feature-enabled library tests, three safe recorder
  tests, one safe D3D12 dimensions test, three helper tests, existing D3D11 native
  suites, two new D3D12 lifecycle cases and 18 native recorder cases (12 WARP/six
  hardware). All configured decode checks passed.
- `scripts/check.ps1` passed formatting, workspace Clippy/tests, frontend typecheck,
  lint and production build. Strict dependency verification passed (545 registry
  packages / 11 direct frontend dependencies); no new package was added.

## Experiments that failed before the final gate

The first replay adapter returned no enumerated source, so RecorderEngine correctly
rejected startup as SourceUnavailable. The test adapter now enumerates only its
explicit owned-fixture ID and rejects other IDs/cadences before device creation.

An initial microsecond-PTS adapter produced a decodable clip with incorrect duration
(roughly 305 seconds instead of under a second). The existing native encoder's raw
input-PTS queue uses the millisecond convention of current production routes. This
adapter now supplies milliseconds, like the established controlled adapter. Added
700–2000 ms replay-duration assertion plus existing MP4 timestamp validation prevent
that false pass. General encoder support for arbitrary input time bases is not fixed
or established by this task; no encoder implementation was changed here.

## Remaining limits / next step

This is an owned offscreen rendering/readback foundation, NOT fullscreen capture or
game readiness. The replay adapter is pull-paced on the recorder worker, not an
independently presenting application. No D3D12 shared textures/fences across
processes, D3D11 encoder GPU bridge interop, arbitrary queue/resource-state ownership,
swap-chain selection, hardware encoder route or performance/soak evidence.

Next is an owned D3D12 swap-chain renderer and capture boundary with explicit queue
ownership, then bounded GPU transport and lifecycle tests. Fullscreen, Alt-Tab,
minimize, source isolation and resize must be measured on that presentation route,
not inferred from offscreen pixels. No protected game was attached, security setting
changed, anti-cheat compatibility established, installer released or commit created.
