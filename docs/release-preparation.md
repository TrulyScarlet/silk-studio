# Release Preparation

This document records the S9 release boundary. A local debug build is not a
release artifact until the preflight, dependency review, media validation, and
signing steps below have completed.

## Build Inputs

- `rust-toolchain.toml` pins Rust 1.98.0 with `rustfmt` and `clippy`.
- `Cargo.lock` and `apps/desktop/package-lock.json` are committed inputs.
- `SILK_BUILD_COMMIT` and `SILK_BUILD_DATE` are supplied by CI. The build date
  must be an explicit reproducible input, not generated by the compiler.
- `cargo tauri build` uses the NSIS target configured in
  `apps/desktop/src-tauri/tauri.conf.json`.
- The configured WebView2 mode is `downloadBootstrapper`; installation needs
  network access if WebView2 is not already present.
- NSIS is a current-user installer. Startup registration, when enabled, is an
  explicit per-user `HKCU` Run value; it does not require machine-wide access.

## Preflight

Run from the workspace root:

```powershell
pwsh -NoProfile -File .\scripts\release-preflight.ps1
```

The warning-mode command is useful on developer machines. A release candidate
must pass the strict form:

```powershell
pwsh -NoProfile -File .\scripts\release-preflight.ps1 -Release -RunAudits
```

Strict mode requires `cargo-tauri`, NSIS (`makensis`), dependency audit tools,
the signing variables, build provenance variables, and `ffmpeg`/`ffprobe`.
`-SkipMediaTools` is only for a non-media packaging investigation and must not
be used for acceptance.

The CI release entry point is:

```powershell
pwsh -NoProfile -File .\scripts\build-release.ps1
```

It runs strict preflight, builds the configured NSIS bundle, signs each
executable with the configured certificate and timestamp service, verifies the
signatures, and writes `target\release\bundle\SHA256SUMS.txt` after signing.

## Signing

The release environment supplies:

- `SILK_WINDOWS_CERTIFICATE_THUMBPRINT`: certificate-store thumbprint used by
  the Windows signing step.
- `SILK_WINDOWS_TIMESTAMP_URL`: RFC 3161 timestamp service URL.

The build pipeline must sign the executable and the NSIS installer, then verify
both with Windows `signtool verify /pa`. Secrets and certificate passwords must
remain in the CI secret store; logs may print the thumbprint only after it has
been normalized and never print a password.

Unsigned artifacts are suitable for local testing only and must not be
published as releases.

## Diagnostics

The application exposes a user-triggered diagnostic export. It writes a JSON
package under the application log directory containing:

- Build identity, target, OS version, DXGI adapter names/vendor ids, driver
  versions, WGC status, and Media Foundation encoder capabilities.
- Redacted settings and a bounded tail of structured log records.
- A filtered recent-error view.
- `mediaIncluded: false`; clip payloads are never copied.

The output directory, selected source, audio device identifiers, profile and
temporary paths, and future structured string values are redacted before the
package is written. Export files are created with unique names and are not
sent anywhere automatically.

## Licensing And Updates

- `THIRD_PARTY_LICENSES.md` remains the review ledger. Provisional rows must
  become approved, with exact lockfile versions and generated notices, before
  publication.
- The exact Gyan FFmpeg 9.0.1 full build is approved as standalone optional
  media-validation tooling not linked into the desktop product.
- Direct MP4 snapshots are produced natively in pure Rust without intermediate
  containers or automatic post-save re-encoding passes.
- There is no updater or update manifest in this milestone. Do not advertise
  update support until a signed-updater ADR, manifest validation, opt-in
  behavior, rollback policy, and tests exist.

## Security Review Notes

- The production CSP allows only bundled assets, the Tauri IPC protocol,
  same-origin connections, and the local Vite development socket. No remote
  application origin is allowed.
- The opener capability is used only after the native clip library validates a
  path against the configured output directory. Diagnostic export accepts no
  frontend-supplied destination path.
- Settings are validated before runtime application and persisted atomically.
- No credentials, accounts, telemetry, cloud upload, process injection, or
  graphics-hook path is present in the MVP.
- `export_diagnostics` creates a package in the native application log
  directory and includes no clip bytes. Its log tail, settings, and future
  structured values pass through the redactor before writing.

## Current Limitations

- `cargo-tauri` 2.11.4, NSIS 3.12, Windows SDK `signtool`, and `cargo-audit`
  0.22.2 are installed in the local development environment. The approved Gyan
  build is installed locally as standalone validation tooling; signing certificate
  material and build provenance remain open for a published release.
- Clean-machine installation, upgrade/uninstall, WebView2 bootstrap, and
  Windows startup registration still require manual Windows testing.
- Hardware encoder bitrate enforcement (`MF_MT_AVG_BITRATE`), player playback
  compatibility across third-party decoders, native capture/audio/GPU recovery,
  and eight-hour resource trends remain hardware-dependent acceptance work,
  not proven by synthetic tests.
